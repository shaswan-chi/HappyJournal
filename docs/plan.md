# 第一版设计说明

## 1. 先做什么

MVP 指“最小可用版本”：用尽量少的功能，完整走通最重要的使用过程。

核心过程：打开首页 → 新建记录 → 输入内容 → 保存 → 首页出现卡片 → 点击回顾。

当前方案按单人、单设备的学习版本设计。它不是面向多人的正式在线服务。后续如果要在多台设备上登录同一个账号，需要增加账号和云端保存。

## 2. 功能范围

| 第一版功能 | 为什么需要 |
| --- | --- |
| 新建记录：日期、文字、可选一张图片 | 文字降低记录门槛，图片方便回忆；限制一张可减少初期复杂度 |
| 首页图文卡片，按记录日期从新到旧排列 | 把过去变成可以浏览的内容 |
| 查看记录全文和图片 | 卡片只显示摘要，详情负责完整回顾 |
| 编辑记录 | 可以补写和纠正内容 |
| 删除前确认 | 减少误删 |
| 本机保存、重新打开后读取 | 记录需要真正保留下来 |

第一版允许一天有多条记录。日期默认今天，也能补写过去；文字必填，图片选填，不强制写标题。相同日期按创建时间从新到旧排列。

暂缓：账号、跨设备同步、公开分享、关注点赞评论、AI 写作、复杂贴纸排版、视频、搜索与统计。先检验“愿不愿意每天记、是否喜欢回顾”。

备份导出与恢复安排在开始长期保存真实日记之前完成，避免学习版本成为重要记录的唯一副本。

## 3. 三个界面

不必先做三个独立网页，可以在一个网页内切换三个区域，减少初期文件与跳转逻辑。

**首页 / 我的回忆**：顶部显示名称和“记录今天”；下方显示图片、日期、文字摘要卡片。电脑显示两到三列，手机优先保证易读，可用单列。先采用规则排列的卡片；高低错落的瀑布流以后再做。

**新建 / 编辑**：日期、文字输入框、选择图片、图片预览、移除图片、保存、取消。新建和编辑共用一个表单，减少重复实现。

**记录详情**：显示日期、完整文字、图片，以及返回、编辑、删除操作。

风格建议：明亮底色、暖黄色点缀、深色正文、圆角卡片，把个人照片作为视觉重点。心情不好也可以记录，不强迫用户写积极内容。

## 4. 容易漏掉的情况

- 没有记录：显示“从今天的一件小事开始”，并提供新建入口。
- 没有图片：显示文字卡片，不放损坏图片或无意义占位图。
- 文字为空：说明需要写一点内容，不保存空记录。
- 图片不支持或过大：说明原因，让用户重新选择；具体限制在实现时确定。
- 保存中：暂时禁用重复保存；失败时保留输入，不显示成功提示。
- 删除：先确认，成功后返回首页。
- 取消未保存的编辑：有修改时提示是否放弃。

## 5. 新手技术路线

推荐从原生 HTML、CSS、JavaScript 开始。“原生”指直接使用浏览器已有能力，不先引入一整套额外开发工具。

| 名称 | 可以怎样理解 | 在本项目中做什么 |
| --- | --- | --- |
| HTML | 网页的内容骨架 | 标题、输入框、按钮、卡片区域 |
| CSS | 网页的外观规则 | 颜色、字号、间距、手机排版 |
| JavaScript | 网页的操作规则 | 点击保存、切换界面、显示记录 |
| IndexedDB | 浏览器内的小型资料柜 | 在当前浏览器中保存文字和图片 |

选这条路线是因为第一版页面少，便于理解每个文件的职责。React 等界面框架可以帮助管理复杂界面，但当前无需先学习这些额外概念。

IndexedDB 可以存放文件和图片数据，比把图片塞进只保存字符串的 localStorage 更适合本项目。不过它的代码比基础页面复杂，因此把它单独放在 storage.js，后续分步实现。

本机保存不等于云备份：不同设备、浏览器及网站地址的数据并不自动共享；清理网站数据、隐私浏览或浏览器回收存储空间都可能让数据丢失。当前也没有账号或日记加密功能。

正式提供多人使用时，再增加“后端”（在服务器上运行、处理账号和数据的程序）、“数据库”（集中存放记录的系统）及图片存储服务。到那一步再根据预算和使用地区选择服务。

## 6. 每条记录保存什么

| 字段 | 含义 |
| --- | --- |
| id | 每条记录独有的编号，用来找到它并编辑或删除 |
| date | 生活事件的日期，可补写过去 |
| content | 用户写下的文字 |
| image | 可选的一张图片数据，不保存只在临时预览中有效的地址 |
| createdAt | 首次创建时间 |
| updatedAt | 最后修改时间 |

用户日记与上传的照片保存在浏览器资料柜中，不写入项目 assets 文件夹，也不随项目源代码发布。
